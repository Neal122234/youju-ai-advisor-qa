有据可查的投资问答助手 · 示例证券。题目：AI 投顾 / 智能问答运营与合规边界；场景：券商 App 内「投教助手」+ 运营后台（券商为虚构的「示例证券」，知识库为匿名构造）

投资问题，有据可答。开户、交易规则、产品知识随问随答；每句回答可点开出处；涉及风险较高的产品按用户风险等级提示；答不了直接转人工。合规要求作为内置底线在后台运行，见下方「核心设计」。项目原名「知界」，旧域名已跳转到新地址。改名后前端按统一视觉规范（web/DESIGN.md，白底 + 单一券商红、分隔线列表、底部出处抽屉）全面重做。

3 分钟体验路径

  • 用户端右侧「演示控制台」可切风险等级 C1–C5、打开「展开技术详情」、选故障注入，并按类型点示例问题：科创板开通条件（「已核实来源 · 引用 N 处」，角标打开底部出处抽屉，C3 用户看到适当性提示，附推荐追问）→ 宁德时代还能上车吗（「超出服务范围」+ 后台告警）→ 市盈率怎么看？茅台还能买吗（「部分问题不在服务范围」）→ 基金赎回多久到账（「已转人工」+ 工单）。
  • 回答下方点「详情」：决策类型、置信度拆解；「完整追溯」跳到后台，看逐步校验时间线、检索命中块与分数、知识版本、模型与耗时。
  • 后台「知识缺口」选中「基金赎回」→ 起草知识 → 发布 v2 → 回归验证，缺口关闭；「知识库」看版本 diff、可回滚。
  • 演示控制台「故障注入」选「大模型报错」：状态变为「知识库原文摘录」，降级作答，合规校验不失效。

核心设计

知识入库Markdown + front-matter（类别、产品风险等级、出处、生效日）；按小标题切分，bge-m3 向量化；每次发布生成 release，答案记录所用版本
检索增强生成向量 + BM25 混合检索；模型只依据资料作答，逐句标引用；逐句证据核验，无依据或含资料外数字的句子剔除
内置合规底线每次问答必经；两层拦截：确定性规则引擎（荐股 / 预测 / 收益承诺 / 代客理财 / 内幕 / 隐私 / 注入）+ 规则放过时的 LLM 意图分类（只会多拦，不会放行）；输出侧再扫描；拒答话术取自知识库合规话术文档并引用
置信度与转人工置信度 = 0.35 检索 + 0.25 覆盖 + 0.25 落地性 + 0.15 引用；≥0.62 作答，0.45–0.62 作答附核实提示，<0.45 或知识未覆盖则转人工，并且不展示模型生成内容
适当性用户 C1–C5 与产品 R1–R5 比对，不匹配时给出提示；所有投资相关回答附统一风险提示
运营闭环答不出 / 低置信 / 差评自动归并为知识缺口；越界触发告警；转人工生成工单 → 起草知识 → 发布新版本 → 回归验证 → 缺口关闭；版本可 diff、可回滚

验证结果

线上评测集86/86　正常 30、混合 10、越界 25、未知 9、注入 4、适当性 5、人工 3（真实模型；QA 第 1 轮修复后在预览部署上不落库全量复跑，正式站复核中）
评测集外盲测第三轮 10 句新问法：10/10 无越界、无编造（其中 1 处决策标签可优化，已写入已知边界）
单元测试257 个用例全部通过（合规规则、切分、检索、置信度、管线异常、接口、QA 回归），CI 测试不过则不发布
独立 QA测试 agent 只测不改，修复 agent 修，再逐条复现回归。第 1 轮 161 个用例，发现 25 个 Bug，修复 23 个，2 个转为已知边界；修复中途一度回归到 82/86，调整后回到 86/86。第 2 轮进行中
接口异常LLM 故障或超时 → 降级为原文摘录；向量服务故障 → 只用关键词检索；数据库故障 → 照常作答并标注；限流返回 429
国内访问站长工具 33 个国内节点（测的是同一基础设施的旧域名）：主站 24 个可访问（含杭州），镜像约 26 个；见 docs/国内访问实测.md

已知边界（摘要，详见 README）

  • 演示后台没有登录和权限控制，写接口无鉴权、CORS 全开，为方便演示保留故障注入（生产环境需接入 RBAC、审批，并关闭故障注入）；chat 限流已改为 D1 全局计数；依赖 Cloudflare 免费额度。
  • 规则加 LLM 两层拦截仍做不到 100%，靠告警复盘和盲测持续补充；镜像的本地模式没有大模型，未知问题可能答非所问。
  • 部分券商口径的数字（两融门槛、风险等级等）为示例，文中已标注「以交易所 / 券商最新规则为准」；系统没有接入真实行情和账户。

全部使用免费资源：Cloudflare Pages Functions + D1 + Workers AI（qwen3-30b-a3b 生成与意图分类，bge-m3 向量）。
