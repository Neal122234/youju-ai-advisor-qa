## 四、Bug 列表

定位以仓库当前代码为准。所有截图在 `scratchpad/qa2/shots/`。

### P1

**N1 工单「重新打开」按钮始终失败（409）**
- 复现：`#/ops/tickets` 选一张已关闭的工单（如 `TK16E494B867`）→ 点「重新打开」。
- 实际：toast 显示"保存失败：工单状态不能从 closed 直接改为 processing（已关闭的工单请传 {"reopen":true} 重开）"，网络请求返回 409。截图 o19。
- 期望：重开为处理中。
- 定位：`web/src/ops/Tickets.tsx:88` 调用 `save('processing')`，`web/src/api.ts:269` `updateTicket` 只发送 `{status, reply}`；后端 `functions/api/tickets/[id].ts:18` 只认 `reopen:true`。这是 B11 修复后前端没有同步改。

**N2 从回答跳到「完整追溯」或「运营后台」再返回，对话全部丢失**
- 复现：用户端问 1 个问题 → 打开「展开技术详情」→ 点「完整追溯」→ 浏览器后退（或点「打开用户端」）。
- 实际：回到欢迎态，消息数为 0（截图 u13）。追溯链接在每条回答下面，用户点一次就丢掉整段对话。
- 期望：保留对话（状态提升到 App 或存入 sessionStorage），或在新标签页打开追溯。
- 定位：`web/src/App.tsx:25` 按路由切换时卸载 `UserApp`；消息只存在 `web/src/user/UserApp.tsx:57` 的 `useState` 里。追溯链接在 `web/src/user/AnswerCard.tsx:152`。

**N3 README 首推的"知识未覆盖"演示题结果不稳定，并会被缓存**
- 复现：`curl … -d '{"question":"基金赎回之后多久能到账？","userRisk":"C5","sessionId":"x"}'`，再用 C3 问一次。
- 实际：C5 返回 `answered_caveat` 0.504，正文是"资金到账时间需根据基金类型和赎回方式确定，具体请参考基金合同…"，引用的 `basics-fund-types` 与赎回到账无关（来源抽屉里没有任何高亮，截图 m04）；结果被缓存，之后同一风险等级每次都一样（latencyMs=0）；**不记缺口、不建工单**。C3 下同一问题是 handoff_unknown。用户端第一次点演示控制台的这道题时（C5）就复现了。
- 期望：转人工 + 缺口（README「30 秒体验」与评测 U03 的预期）。

其他接口的行为变化：
- `POST /api/kb/rollback`：目标版本从未发布过（draft）时返回 400 `NOT_PUBLISHED_VERSION`。前端只应对 archived 版本显示「回滚到此版」；当前发布版本应显示「下线」，调用 `unpublishDoc`。
- `POST /api/gaps/:id {action:'draft'}`：返回 `docVersionId: null`，以及预填的 `content / title / category / productRisk / docKey / gapId`。前端「起草知识」应只把这些内容填进编辑器；保存时调用 `saveDoc({..., docKey, gapId})`，此时才生成草稿。
- `POST /api/eval/run`：前端评测页应传 `persist:false`（N16），并用 `limit` 分批，例如 `{offset, limit:8, persist:false}`。
